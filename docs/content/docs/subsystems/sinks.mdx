---
title: Sinks
description: Event output targets (stdout, file, S3 and custom) and how retention archives through them.
---

Sinks are secondary output destinations for audit events. Today the one thing in Chronicle that writes to a sink is retention: before it purges expired events, it archives them to the archive sink if the policy asks for that (see [Sinks in retention](#sinks-in-retention)).

`Record()` doesn't write to sinks. Nothing fans recorded events out to them, so a sink you build and don't hand to retention only receives what your own code writes to it.

## Sink interface

```go
type Sink interface {
    Name() string
    Write(ctx context.Context, events []*audit.Event) error
    Flush(ctx context.Context) error
    Close() error
}
```

Sinks receive batches of events. `Write` delivers the batch, `Flush` drains any internal buffer, and `Close` releases resources.

## Built-in sinks

### Stdout

Writes JSON-encoded events to an `io.Writer`. Useful for development and log aggregation pipelines.

```go
import "github.com/xraph/chronicle/sink"

s := sink.NewStdoutSink(os.Stdout)
```

### File

Writes JSONL files (one event per line) to a directory, named `<prefix>-*.jsonl`. `sink.WithMaxSize(bytes)` rotates to a new file past that size.

```go
s := sink.NewFileSink("/var/log/chronicle", "audit", sink.WithMaxSize(100<<20))
```

### S3

Uploads batches of events as gzip-compressed JSONL to an S3-compatible object store. It takes anything with a `PutObject(ctx, bucket, key string, body io.Reader) error` method (`sink.S3Writer`), so you adapt your S3 client to that.

```go
s := sink.NewS3Sink(s3Writer, "my-audit-bucket", "prefix/")
```

### Multi

Fans out to multiple sinks. If one sink returns an error, the others continue, and you get the combined error back.

```go
s := sink.NewMultiSink(logger, stdoutSink, fileSink, s3Sink) // logger may be nil
```

## Custom sink

Implement the `Sink` interface to write to any destination:

```go
type KafkaSink struct {
    producer kafka.Producer
    topic    string
}

func (k *KafkaSink) Name() string { return "kafka" }

func (k *KafkaSink) Write(ctx context.Context, events []*audit.Event) error {
    for _, ev := range events {
        b, _ := json.Marshal(ev)
        k.producer.Produce(&kafka.Message{
            TopicPartition: kafka.TopicPartition{Topic: &k.topic},
            Value:          b,
        }, nil)
    }
    return nil
}

func (k *KafkaSink) Flush(ctx context.Context) error {
    k.producer.Flush(5000)
    return nil
}

func (k *KafkaSink) Close() error {
    k.producer.Close()
    return nil
}
```

## Sinks and the plugin system

The `plugin` package declares a `SinkProvider` interface, and `plugin.Registry` collects the plugins that implement it. Nothing in Chronicle reads that collection, though: `Record` doesn't fan out to registered sinks. To archive through a sink, pass it to retention.

## Sinks in retention

The retention system uses a `sink.Sink` as its archive sink. Events matching a policy with `Archive = true` are written to the archive sink before being purged from the primary store. Configure it with `extension.WithArchiveSink(s)`.

Sinks only write. To read an archive back, which the retention backfill needs, use `sink.NewFileArchive` for a `FileSink` directory or `sink.NewS3Archive` for an `S3Sink` bucket. Both implement `sink.ArchiveReader`.
